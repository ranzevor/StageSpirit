# 发行流程

本文面向维护者，说明从已审查源码准备版本、构建制品和核对下载结果的步骤。当前软件版本及支持环境由版本与兼容说明维护。

[版本与兼容](compatibility.md) · [贡献与审阅](../../CONTRIBUTING.md)

## 准备版本

1. 明确发行目标、支持环境和包含的变更，核对需求、公共接口及数据格式影响。
2. 在版本唯一来源更新版本，按同一值同步快速开始中的版本输出与支持表。
3. 准备发行说明，列出用户可见变化、兼容影响、迁移步骤、已知问题和恢复方法。
4. 对候选运行文档、格式、类型、契约、行为和安装检查，检查引入材料的许可及分发范围。
5. 通过 Pull Request 完成源码审阅，核对实际合入提交与所测对象。

[检查入口](engineering.md#开发环境与检查)

## 构建与安装

在对应版本源码和锁定环境中运行。

```shell
uv sync --frozen
uv build --sdist --wheel --no-build-isolation
```

`dist/` 生成 wheel 和 sdist。检查包元数据、依赖、项目许可、README 本地图片和源包中的开发检查入口。源包应能在独立目录中重新构建 wheel，wheel 在独立环境中安装后完成帮助、版本及 MCP 调用。

可重建的环境由 `.python-version`、`pyproject.toml` 和 `uv.lock` 定义。发行说明关联准确源码提交和构建工具，随制品提供校验信息。构建缓存与发行文件按各自用途维护。

## 发布与读回

取得该次公开发行授权后，以已审查提交创建对应的 `v<版本>` 附注标签，再创建 GitHub Release 并上传同次构建的制品。标题和说明使用简体中文，版本标识保留原文。

发布前读取目标版本占用，发布后从下载入口核对标签所指提交、制品集合、校验信息与安装结果。上传响应缺失或部分成功时，先查询已经发布的对象，再补齐缺项。

[发行入口](https://github.com/ranzevor/StageSpirit/releases)

## 更正与恢复

未发布候选可以修正并重新检查。已发行版本的修复使用新版本和新标签，说明受影响版本及替代方法。发生安装或兼容问题时，保留原发行信息，将更正和恢复方法发布到同一版本的说明入口。

停止支持某个版本或环境时，同步更新支持表、安全报告说明和迁移入口。使用者已经保存的程序与数据按照各自版本恢复。
