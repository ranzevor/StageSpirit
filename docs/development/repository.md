# 仓库结构与文档维护

本文面向项目维护者，说明 StageSpirit 整个项目的内容归属、文档职责及变更方法。目录按实际用途组织，并随实现演进。

## 项目内容

| 位置 | 职责与维护来源 |
| --- | --- |
| src/stagespirit_mcp/ | 后端源码及接入层 |
| web/stage/ | D5 展台前端的目标位置，随前端实现建立 |
| docs/product/ | 产品目标、使用场景、范围和独立身份 |
| docs/requirements/ | 首版需求规格、责任与预期结果 |
| docs/architecture/ | 模块关系、状态所有权及跨模块接口设计 |
| docs/design/ | 首版契约、工作流及各专题的状态与恢复设计 |
| docs/reference/ | 当前已实现的 MCP 接口与中英文术语 |
| docs/adr/ | 架构选择、理由、代价和改选条件 |
| docs/guides/ | 当前版本的安装、调用及错误处理 |
| docs/development/ | 开发约定、目录职责与实施计划 |
| docs/testing/ | 测试方法与具体验收场景 |
| docs/standards/ | 采用的规范身份、适用范围和检查入口 |
| contracts/ | 共享 Schema 和工具边界设计的维护源 |
| docs/assets/ | 文档使用的品牌图标 |
| examples/mcp/ | 可运行的 MCP 客户端示例 |
| examples/contracts/ | 人工维护的接口正例 |
| tests/fixtures/contracts/ | 按 Schema 分类的测试反例 |
| scripts/ | 实际需要的开发维护脚本 |

运行配置、凭据、数据库和用户媒体使用独立应用数据目录。构建输出、缓存和虚拟环境属于可重建产物，源码和必要测试数据纳入版本管理。

## 正文职责

需求规格维护功能结果与适用条件。设计解释实现机制，接口参考描述字段和协议，指南把对应能力组织为操作步骤。术语在参考目录统一定义，技术选择在 ADR 中说明背景、备选、选择、影响和重新选择条件。

每篇正文的开头说明目标读者、用途和适用范围。目录入口按读者任务链接到正文，稳定的需求和验收场景标识用于关联设计与测试。

## 更新文档

1. 修改功能或范围时，先更新相应产品范围和需求条目，保留稳定需求标识。
2. 按责任更新架构、专题设计、契约及 ADR 中受影响的机制。
3. 同步示例、调用指南和验收场景中的字段、单位、步骤及预期。
4. 新增目录时提供任务入口，移动正文时更新所有实际引用。
5. 从项目首页沿对应阅读路径检查本地目标及章节，实读修改后的需求、设计和调用步骤。

## 契约与生成资料

设计阶段直接维护 contracts 中的 Schema、工具边界及相应示例。实现时，完整工具输入输出和路由由同一类型化注册表产生。共享 Schema 按各自维护源生成或引用，运行状态由 RuntimeSummary 生成。生成接口资料标明对应生成入口，修改通过维护源完成。工具目录描述业务边界，生成结果按该边界核对名称、分组、分页和副作用。生成方式见契约说明。

[契约说明](../../contracts/README.md#已实现契约的生成)

同一机制只在所属正文定义，导航和指南引用该正文。需求与验收用稳定标识关联，源码形成后沿实际模块和测试入口补充定位。

文档以中文（zh-Hans）维护，代码标识符采用准确原名。文件版本及路径变化由 Git 维护。
