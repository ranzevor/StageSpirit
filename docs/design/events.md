# 直播事件与可靠消费

本文面向平台适配及事件消费实现，说明统一事件的业务字段、保存、水位、去重和规则动作。

平台适配器将外部事件归一化。事件与待分发记录在同一事务保存，通知、展台和规则消费者分别推进水位。

## 必要业务字段

| 对象 | 内容 |
| --- | --- |
| 身份与时间 | 事件 ID、平台、连接、历史来源快照、数据代际、发生与接收时间、可用的上游消息 ID |
| 观众 | UID、昵称、用户等级、会员、舰队等级、粉丝牌及等级 |
| 正文 | 完整聊天、SC 留言、礼物附言和会员续费正文 |
| 礼物与会员 | 名称、数量、平台礼物身份、批量关系和会员计划 |
| 价值 | 本次事件总价值、单位、币种及实际付费属性 |
| SC 展示 | 上游提供的开始和结束时间 |
| 平台扩展 | 白名单业务字段，例如 coin_type、total_coin、plan、viewer_count |

source 保存事件接收时的来源快照，source_id 必填并表达真实房间或频道，display_name 和 broadcast_id 在上游提供时保存。连接目标或名称后续变更不改写历史快照，也不使用后来的配置补填来源。

sequence 是运行配置当前 data_generation 内单调递增的本地接收序列，用于稳定排序。after_sequence 续读同时携带所属 data_generation。数据恢复切换生成新的 data_generation，旧代际水位和游标返回 DATA_GENERATION_CHANGED 及当前代际，调用方重新建立快照。received_at 始终保存本地接收时间，occurred_at 仅在上游提供时保存。观众身份按上游实际字段传递，匿名事件保留 is_anonymous，缺少 UID 时省略该字段。

金额使用十进制字符串，数量使用整数。value.amount 表示本次事件总价值；只有确认单价与数量关系后才计算总价。积分、银瓜子和 Bits 保留原单位，自定义平台单位通过 platform_unit 与 unit_name 表达。只有已知完整数值关系时同时提供 unit_value 和总 value，并校验单位与币种一致。未知字段省略，0 和 false 保留。

通知直接发送[事件对象](../../contracts/schemas/live-event.schema.json)，保留必要字段和完整正文。大段原始载荷只进入受限诊断存储。字幕的方括号清理只作用于 TTS 字幕，不改写观众消息。

## 接收与水位

持久事务提交后才推进本地接收状态。平台提供确认或补拉时按其能力使用；平台没有重放能力的断线窗口记录接收间断，后续仍继续接收。

有稳定上游消息 ID 时，去重同时使用连接、历史来源和适配器声明的上游 ID 作用域及其值。作用域按平台实际规则区分房间、频道或单次直播，重连保持同一作用域，连接切换目标后使用新来源。没有稳定 ID 时保留独立本地事件，避免把同用户相同文本的多次真实发言合并。

通知、展台和规则消费者各有带数据代际的水位。一个消费者失败不撤销已保存事件，也不阻塞其他消费者。历史分页固定 data_generation、筛选和快照上界，后续页使用相同条件及稳定序列。保留清理记录表明续读所需事件已被删除时，返回 HISTORY_GAP 及最早可读序列，调用方据此选择新的消费起点。筛选排除的事件和未分配的序列不作为历史缺口。

## 规则与动作身份

过滤规则区分隐藏展示、禁止动作和正文替换。展示替换不覆盖已接收正文。正则有执行预算，超预算只使该次规则执行失败。

规则消费者第一次处理事件时固定规则修订和动作计划。动作身份由事件、规则及其修订、动作序号组成，事务内唯一创建，并映射到一个 runtime 操作。重投与进程恢复复用该计划和操作，不能以新规则重新解释旧事件后再次播报。

配置更新作用于此后首次评估的事件。显式重新处理历史事件使用新的独立请求，调用方能区分它与自动恢复。冷却条件和动作创建在同一协调边界内检查，避免并发绕过。

## 保存与清理

默认保存已接收业务事件，按显式保留策略清理。未完成分发和恢复所需的记录受保护。磁盘失败返回具体持久化错误；已落库事件可通过历史继续读取。

接口和错误见[MCP 契约](../reference/mcp.md)，动作协调见[内部接口](../architecture/interfaces.md)。
