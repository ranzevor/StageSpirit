# 运行时与操作生命周期

本文面向运行时实现，说明实例、连接、任务与操作的生命周期，以及并发、取消和恢复机制。

运行时拥有任务监督、实例生命周期和操作账，连接客户端由所属业务模块持有。运行配置中的 enabled_capability_groups 决定启用的业务工具组。一个运行配置对应一个控制实例；MCP 请求共享受管理连接。业务模块负责自己的完成判据和外部状态回读。

## 启动与关闭

启动依次完成路径解析、实例锁、数据库版本检查、兼容的事务迁移、配置与凭据加载、模块装配及接入启动。需要维护窗口的数据格式切换按[存储设计](storage.md#导入迁移与保留)处理。自动连接只使用已保存偏好。未完成配置激活可恢复；语音、推流和录制命令不会作为启动动作重放。

关闭先停止受理新命令，再协调取消、释放参数和音频设备、关闭连接，最后保存操作状态。同步 SDK 使用受管理工作队列；线程中的调用需要等待结束或记录尚未确认的外部结果。

连接失败只影响该连接及其依赖。状态记录目标地址、连接代际、实际错误和最近成功观察；连接请求失败不推导成目标应用进程未启动。

## 请求上下文与受理

runtime_status 返回 profile_id、data_generation 和实例身份。所有业务变更请求携带当前 data_generation；条件写入同时核对 expected_revision。DATA_GENERATION_CHANGED 返回当前代际，调用方刷新对象与修订后组织新的业务请求。

幂等身份包含首次受理的数据代际。旧代际的重复请求先只读查找原操作，已受理的请求返回其原结果及受理时的 data_generation；没有原操作时拒绝受理。查询历史操作保留其原受理上下文，当前数据代际以 runtime_status 为准。数据恢复后，旧幂等键不会隐式变成一次新的播放或外部写入。

MCP 传输取消或客户端断开只终止该请求的等待。已受理的持久操作继续按自己的生命周期执行，显式 operation_cancel 才请求取消它。受理落库前的请求可以直接停止，受理后返回或保留可查询的操作身份。

## 操作状态机

| 当前状态 | 允许转移 | 判定依据 |
| --- | --- | --- |
| accepted | queued、running、cancelled、failed | 受理已落库；尚未产生外部效果 |
| queued | running、cancelled、failed | 取得执行资源或被取消 |
| running | completed、failed、cancel_requested、outcome_unknown | 业务完成、已知失败、取消请求或外部结果待核对 |
| cancel_requested | cancelled、completed、failed、outcome_unknown | 执行方终止及实际效果回读；完成与取消允许竞争 |
| outcome_unknown | completed、failed、cancelled、running | 原操作核对结果；仅确认可继续时增加执行代际并续作 |
| completed、failed、cancelled | 保持终态 | 后续回执只补充事实，不复活任务 |

[操作详情](../../contracts/schemas/operation-detail.schema.json)分别表达执行状态、已发生效果和恢复状态。取消成功保留已播放声音、已生成文件或已执行命令的效果记录。

## 幂等与恢复

带副作用的长操作以运行配置、数据代际、工具、目标和幂等键唯一标识，保存规范化输入摘要。并发相同请求取得同一操作；同键不同输入返回冲突。执行前在事务内占用操作记录，执行后保存实际回执。

省略目标而使用默认连接的请求，先按默认目标槽位与幂等键查询原操作。首次受理固定实际连接、模型、音色及语音设置，重复请求沿用原操作的解析结果。显式目标请求按其目标范围去重。

幂等记录至少覆盖任务执行和恢复窗口。有效记录不因普通缓存清理丢失。写入超时先核对原目标：确认完成则结束，确认未执行且允许续作时重试同一操作，仍未知则保留核对入口。

进程重启后，未产生外部效果的排队任务按其恢复策略处理；已开始的外部操作进入核对。语音播放不自动从头重播。OBS 可回读操作根据保存的目标和步骤恢复。恢复续作通过原操作的状态比较与执行代际占用，多个恢复请求不能同时获得执行权。

数据库恢复生成新的 data_generation。维护切换记录、当前恢复操作及必要的原操作去重身份在切换后仍可读取；历史操作的外部效果按原目标重新核对，旧分发记录不能作为新代际动作重新派发。

## 并发与代际

连接重建、模型切换和播放替换分别增加代际。参数批次和回调携带代际及操作身份，旧回调可补充旧操作的收据，但不能写入当前模型或推进新任务。

同目标 OBS 写入使用资源租约；同步 SDK 套接字串行访问。音频设备只有一个播放所有者，speech 内部播放阶段与通用操作状态分开维护，已进入 running 的合成任务等待播放时保持 running。参数租约切换按实际目标和模型代际协调，每次授予具有独立 lease_id，写入及释放同时核对当前授予身份。配置更新使用期望修订，网络重配置在数据库事务之外执行。

## 队列

业务命令队列有可配置容量，满时返回 QUEUE_FULL 或保留在持久化动作分发记录中等待执行。speech 的首版待播容量默认 64、合成并发默认 2，顺序及打断保留权见[播放队列](speech.md#播放队列)。持久动作尚未取得目标队列名额时保留原分发身份，进入队列后复用原操作与入队序号。上传与解码预算、其他命令队列容量、列表快照租约数量及有效期分别配置并在所属阶段固定；超过资源预算返回 RESOURCE_LIMIT，回执区分未受理与已受理操作。实时音量和进度通道保留最新有效帧，结束和释放信号使用独立控制通道及持久终态。消费者在释放确认前重试清理，租约到期、断线和代际失效也触发释放。

平台事件先保存再分发。磁盘失败明确报告未持久化状态；通知和规则消费者分别管理水位。具体策略见[直播事件](events.md)。
