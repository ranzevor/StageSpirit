# 语音与字幕

本文面向语音、转写与字幕实现，说明提供方能力、音色发现、文本视图及实际播放的协作。

speech 负责提供方、文本准备、合成、音频资源和播放。transcription 负责转写。字幕由 stage 从播放事实生成视图，语义动作由 performance 独立调度。

## 提供方与音色

提供方声明音色目录、语言、PCM、流式输出、速率、音高、音量、风格和发声标签能力，输入按该提供方配置校验。首版覆盖六类 TTS 提供方，见[范围](../product/scope.md)。

OpenAI 兼容适配器使用包含版本路径的基础地址，分别调用 /audio/speech 和 /audio/transcriptions。VoiceStudio 是该类适配目标之一；连接鉴权由服务配置决定。

音色项包含稳定 ID、名称、提供方、语言、来源，以及必要的模型和后端选择。目录来源区分服务发现、固定目录、手工配置和仅当前配置值。发现失败、无目录接口和空目录分别返回。临时查询不切换播放连接，目录按[MCP 契约](../reference/mcp.md)分页。

voice_list 的 VoicePage 同时返回目录来源、获取时间、完整性和发现状态，空 items 仍保留这些信息。刷新只在首次查询发起并生成新目录快照，后续 cursor 固定该快照，不能同时请求刷新。临时查询使用单独配置的连接，保持默认连接和当前播放不变。voice_id 在连接与目录中唯一，voice_get 返回可复用的模型及后端选项。

OpenAI 兼容音频接口的音色发现由适配器的目录能力或显式目录端点配置决定，目录按目标后端格式解析。仅当前配置值以 configured 来源返回，并标明 complete 为 false。目录请求失败保留具体错误；没有目录接口时返回 unsupported 状态，可同时列出已配置的音色。

## 文本投影

| 文本 | 所有者与用途 | 规则 |
| --- | --- | --- |
| 请求正文 | 调用方 | 保留完整输入和文本模式 |
| 合成正文 | speech | spoken 模式移除已识别的中文括号表演提示，保留正常说明；verbatim 保留原文；ASCII 方括号内容原样传给提供方 |
| 字幕正文 | stage | 从合成正文删除所有 ASCII 方括号块及其中内容；支持嵌套、多行和未闭合尾部；清除残留方括号标记 |
| 匹配正文 | performance | 排除发声标签后分句匹配关键词，并保留与当前播放片段的关联 |

例如合成正文为 `[laughter]真的成功了！[任意提示]`，字幕为 `真的成功了！`。方括号过滤不使用词表，也不随引擎改变。纯标签发声继续播放音频，字幕处于 hidden 状态。

spoken 的中文括号提示识别使用 speech 配置中的表演提示词及组合规则，同时支持中文全角括号和含中文提示的半角括号。仅当完整括号片段匹配表演提示时移除，例如“（轻笑）”和“（压低声音，停顿）”；“价格（含税）为 30 元”等正文说明保留。提示词可在语音配置中维护，处理结果保留原文字符区间供后续投影关联。

字幕按字符深度扫描 ASCII 方括号，进入左括号后忽略内容，嵌套块到相应闭合处结束，未闭合块忽略至文本尾部，孤立右括号移除。标签外的文字、数字和标点保持原顺序。字幕显示、编辑预览和分句模式共用同一投影规则。投影不修改 TTS 请求、队列文本和原始播放事实。发声标签是否产生声音由提供方能力决定。相关选择见 [ADR 006](../adr/ADR-006-text-projections.md)。

## 合成与播放

[语音请求](../../contracts/schemas/speech-request.schema.json)只表达语音参数，不携带模型语义映射。受理时固定实际连接、提供方配置修订、模型、音色、文本准备规则和语音参数，排队期间保留该合成输入。语义规则仍在播放开始及更新时按 performance 的活动修订选择。缓存键包含实际服务目标、提供方、后端、连接合成配置指纹、模型、音色、合成正文、实际参数和文本规则版本。凭据以身份及轮换修订参与缓存身份计算，明文密钥不进入缓存键或日志。合成结果默认返回文件资源，播放是独立阶段。

[播放事件](../../contracts/schemas/playback-event.schema.json)包含 prepared、started、progress、finished、interrupted 和 failed。事件的 clock.kind 表达播放时钟，状态查询中的 playback_clock 使用相同取值。pcm 位置来自实际已播放采样数，provider_timestamp 位置来自提供方实际播放进度，只有生命周期的原生播放使用 native_lifecycle。合成阶段返回的分段时间戳单独用于正文对齐，不作为实际播放进度。仅支持原生播放的适配器声明文件合成能力不可用，speech_synthesize 返回 UNSUPPORTED_CAPABILITY。

正文对齐记录 alignment_source，取值为 provider_timestamp 或 text_estimate。提供方对齐信息把合成正文码点区间映射到音频区间。speech 通过只读 PlaybackAlignment 端口提供可用状态、对齐修订和资源引用，按区间读取 cue；流式对齐更新发布 PlaybackAlignmentChanged，具体边界见[内部接口](../architecture/interfaces.md#事件身份与时间)。可播放 PCM 但没有正文时间戳时，仍由 pcm 时钟推进播放位置，正文片段采用 text_estimate 对齐。原生播放的 started 事件发布播放器的 started_monotonic_ms 和 clock_epoch，后续终态保留同一组值。消费者沿用该起点估算位置，延迟收到事件时不按收件时刻重新起钟。不同 clock_epoch 的单调时间不可比较，重启后先核对原操作。native_lifecycle 不产生 progress。

播放事件携带语音 connection_id 和 data_generation，订阅按运行配置和连接路由到指定字幕组件、形象及语义配置，消费者拒绝旧数据代际。字幕从 started 开始显示，终态按当前播放身份清理。字幕组件使用递增 state_sequence 排序显示、分句及隐藏状态，初始 hidden 可以没有播放身份。嘴型只消费实际音频包络。分句调度分别保留播放时钟和正文对齐来源，规则见[形象与表演](avatar-performance.md#播放位置与调度)。

## 播放队列

同一运行配置的播放槽位使用一条待播队列，实际音频设备始终只有一个播放所有者。priority 的范围为 0 至 9，默认 5，数值大者先执行；相同优先级按受理事务分配的 enqueue_sequence 升序执行。序号在同一 data_generation 内持久递增，重复幂等请求复用原操作及序号。

受理即入队，合成可以并行。派发时先确定优先级最高且序号最早的队首；队首音频尚未就绪时，后面的低优先级或同级任务继续等待。新到的更高优先级任务可以成为新的队首。只有队首准备完成并取得播放权后才进入 starting，此后新的高优先级请求不能改变本次播放选择。只支持原生播放的提供方以本地校验及调用输入就绪作为准备完成，started 仍由实际播放开始产生。

首版默认每个运行配置最多保留 64 个待播项，不计已持有播放权的任务；显式打断的替代任务在取得播放权前也占一个待播名额。默认合成并发为 2，适配器声明的上限更低时采用较低值。这两个值持久保存在 speech 配置中，降低容量只影响后续受理，降低并发等待现有合成自然退出。队列满时在受理前返回 QUEUE_FULL，已有任务保持原顺序。优先级只决定尚未取得播放权的任务次序，任务保留到实际执行、显式取消或已知失败。

队列内的待合成、合成中、音频就绪及 starting 是 speech 的内部阶段；操作一旦因合成进入 running，后续等待播放不会回退为 runtime 的 queued。started、终态及其分发记录持久保存，进度快照和 PCM 帧只保留有界的最新状态。进程恢复沿原操作核对，已开始声音不从头重播。

## 显式打断与停止

interrupt_current 默认为 false。为 true 时，先查原幂等操作，再校验输入、队列容量及当前 starting 或 playing 旧任务所属适配器的实际停止能力。持久受理、登记切换及固定旧播放身份处于同一播放槽位协调边界。受理后替代任务取得一次性的下一播放者保留权，同时向该旧播放请求停止。该保留权先于普通队列，与替代任务自己的 priority 无关。设备空闲时直接沿保留权准备启动。

同一播放槽位只允许一个未完成的打断切换，后到的新打断请求在受理前返回 PLAYBACK_SWITCH_BUSY；相同幂等请求返回原操作。有旧播放且其适配器不支持停止时在受理前返回 UNSUPPORTED_CAPABILITY；空闲槽位没有停止能力前置要求。受理失败不会触发停止。

替代任务等待自己的音频就绪，并等待旧播放已确认终止、音频设备及相关控制租约释放后启动。替代任务取得播放权并进入 starting 时消费下一播放者保留权，完成本次切换；后来的新打断可以针对这个当前任务受理。停止结果未知时沿原操作核对，替代任务继续等待，也可以被显式取消。替代任务合成失败或取消后释放保留权，普通队列恢复 priority 降序、enqueue_sequence 升序的派发；已经停止的旧声音保留实际播放位置和终态。

自然结束与停止竞争时按实际观察记录 finished 或 interrupted。speech_stop 只影响明确指定的操作，停止排队任务会移除该项，停止在播任务会释放其设备和控制租约，其余待播项继续按上述规则执行。

## 转写

转写接受授权文件资源或受控上传，校验格式、大小、时长和解码结果。语言及上下文提示传给对应提供方，结果保留完整文本，附带上游实际提供的分段和时间信息。

取消和上传超时按[操作状态机](runtime.md)处理，先查询原操作及已保存结果，避免重复提交。
