# 展台与 OBS 应用

本文面向展台及 OBS 接入实现，说明编辑、准备、应用、资源归属、结果核对及失败补偿。

stage 拥有编辑修订、候选、应用计划和补偿记录；broadcast 拥有 OBS 连接及资源写入协调。编辑、保存、准备和应用分别表达。

## 编辑与合成计划

展台包含画布、皮肤、布局、组件及媒体引用。弹幕、字幕、白板、公告、模型和窗口捕获各自保存业务状态。编辑批次携带 expected_revision，事务内全部提交或拒绝；新编辑使对应重做分支失效。

编译布局时按层序排列组件。不透明皮肤在最低层绘制一次全画布背景，上方的 Web 组件平面保持透明；透明皮肤按其透明背景定义合成。布局以原生捕获开头或没有可见组件时，不透明皮肤仍具有底层背景。皮肤切换重新计算背景责任并清除旧内联背景覆盖。

连续 Web 组件组成平面，原生模型或捕获来源按绑定插入其间。捕获框的底饰与前景框饰按各自层序分开安排，前景边框、标题及覆盖控件放在对应原生捕获之上；以捕获结尾时也保留需要的前景平面。计划逐平面标明背景绘制和框饰责任，渲染端据此生成画布。

平面数量由实际层序决定，计划保留来源身份、变换、裁剪、可见性、资源清单及相对顺序。画布尺寸、背景像素、捕获区域透明性和框饰位置由确定的合成样例验收。

组件、笔迹、媒体、预设和修订分页查询；完整项目导出使用文件资源。

## Web 与 MCP 状态同步

MCP 与 Web 编辑接口调用相同的 stage 应用服务。编辑事务提交修订和分发记录后，Web 订阅收到数据代际、项目、修订及变更类别，按修订重新读取元数据和受影响组件。写入回执携带提交修订，发起端以该修订更新视图。浏览器内存只保存编辑视图和未提交输入。

快照包含 data_generation、布局修订与各组件状态序列。订阅从快照水位续读；传输无法直接按水位续流时，先建立订阅并缓冲，再读取快照，只应用快照水位之后的消息。重连使用同一衔接流程，水位过期时重新读取快照。编辑端和输出端在同一代际内只推进修订及状态序列，迟到的写回执、读取结果和重复通知均不能回退新视图。数据代际变化后清除旧读取上下文，再取得新的快照。

已应用输出固定布局修订及资源引用，项目草稿与播出布局分别查询。set_layout、set_skin、apply_preset 和组件结构变更进入待应用布局；白板文字、笔迹、公告内容等命令在提交持久修订的同一事务内更新组件数据并保存状态通知。undo、redo 也发布对应内容状态。聊天、字幕和其他运行数据通过组件身份与独立状态序列更新。布局编辑更新编辑端与草稿预览，stage_apply 完成后切换播出布局；运行数据更新直接传到引用该组件的输出。

组件详情返回固定设置、当前内容序列和集合入口。笔迹、公告及展示聊天分别分页读取；单条公告通过详情工具读取，聊天保留对应 event_id。客户端按序列去重，发现缺口后读取对应状态快照。仍被在播布局引用的组件数据保留到输出释放。

字幕视图包含独立 state_sequence；尚未播放时以 hidden、空正文及当前组件序列表达初态，之后的播放关联字段成组出现。分句显示、手动隐藏与终态清理推进该序列，并校验当前播放身份，旧播放终态不能清理新字幕。

编辑变更、运行状态和布局就绪分别使用类型化消息。只读输出仅订阅候选授权范围内的组件；字幕投影规则由 stage 统一执行，编辑预览与播出使用相同结果。

## 准备

stage_prepare 只读取 OBS，核对目标和已有来源，生成本地候选及[预检结果](../../contracts/schemas/stage-preview.schema.json)。准备阶段不创建来源、不占用长期写锁。结果绑定 data_generation、profile_id、项目修订、连接代际、规范化实际目标 target_id、场景原生身份、output_slot_id、计划摘要和过期时间。连接代际用于前置条件核对，重连不改变实际目标和输出槽位。

同一实际 OBS 目标场景同时由一个 StageSpirit 项目拥有受管舞台布局。预检通过 occupied_output 返回占用方的 profile_id、project_id、output_id、output_slot_id、state_sequence 和生命周期固定摘要，并将这些事实绑定计划。同项目同槽位再次应用自动替换原输出。另一项目接管时，stage_prepare 必须显式提供当前 profile 内已有的 replace_output_id，并核对其正是该目标场景的占用输出。未提供、目标不符或归属不符均返回 OUTPUT_CONFLICT。跨 profile 占用先在原 profile 显式释放，不能通过连接别名、另一项目或另一 profile 自动接管。

显式 replace_output_id 固定在预检中，stage_apply 只引用 preview_id，不重新传入替换对象。应用前重读旧 owner、output_id 和 state_sequence；占用方或序列已变化时返回 OUTPUT_CONFLICT 并重新准备。候选与旧输出同时存续所需资源计入预算，资源不足在新请求受理或准备阶段返回 RESOURCE_LIMIT，保持既有输出。

已存在的 VTS 或捕获来源通过身份和类型回读确认。准备阶段不调用 OBS CreateInput；缺少明确绑定时返回对应项的原因。详细变更通过 stage_preview_changes_list 分页读取。

计划逐项列出将修改的场景项属性、来源设置及排序容器。既有来源绑定区分只读来源引用和明确授权复用的场景项。只读来源引用创建本展台的场景项，变换与裁剪只作用于新引用；复用既有场景项时，仅修改绑定允许的属性。将复用项纳入受管层序需要明确的排序权限，缺少权限时预检返回具体绑定冲突，由调用方选择新的只读引用或调整授权。

受管展台场景项放在目标场景底部，内部层序与布局一致，区外场景项的相对顺序保持原值。全局来源设置、场景项属性和所属场景或组的排序分别确定可写范围。场景项身份包含所属容器，嵌套项核对父组路径及对象身份。

准备时枚举全局来源在其他场景或组的引用。需要更新的浏览器输入已经被写入范围之外的对象共享时，计划创建独立输入及受管场景项，保留已有共享来源供原引用使用。同名、相同 URL 或 StageSpirit 名称前缀均不自动建立归属，显式绑定和受管记录分别确定读取及写入责任。

## 应用状态

| 阶段 | 动作与完成条件 |
| --- | --- |
| claim | 占用原幂等操作，取得实际目标场景的跨进程排他租约和受影响资源租约 |
| revalidate | 核对预检有效期、修订、连接代际、实际目标及旧 owner、output_id、state_sequence |
| snapshot | 在写入之前保存受影响对象的完整设置、场景项状态及目标中受保护的相对顺序 |
| prepare_output | 在本次受管候选范围内准备浏览器输出和必要资源 |
| ready | 回执的应用、修订、平面和资源清单匹配，布局已就绪 |
| apply | 执行来源计划，保留当前节目场景 |
| verify | 回读目标、变换、可见性、地址及受管层序；比较其他来源设置与场景项相对顺序；显示的平面取得绘制确认 |
| activate | 在 verify 完成后原子切换该槽位及目标场景的 owner，保存实际生效修订 |
| retire_previous | 按旧输出的引用与授权清理已退出对象；有计划外共享引用的旧输出转入 retained |
| completed | 保存输出与资源归属，发布 StageApplyResult 结果资源 |

应用请求见[Schema](../../contracts/schemas/stage-apply.schema.json)。过期预检返回 PLAN_EXPIRED，目标漂移返回 TARGET_CHANGED，只重新准备受影响计划。需要切换节目场景时调用独立的切换操作。

ready 表示布局、字体和所需资源已加载并完成布局，painted 表示显示后完成绘制。回执校验数据代际、应用操作及执行代际、output_id、平面、修订和资源清单；旧连接或旧输出回执不推进当前操作。隐藏场景通过 OBS 可见性和布局回执确认准备状态。活动输出必须已经 ready，painted 为 true 时同样要求 ready 为 true。隐藏活动输出允许 painted 为 false，显示后的绘制确认按实际输出完成。

stage_apply 的操作详情通过 result_resource_id 提供 StageApplyResult，成功结果包含 profile_id、output_id、project_id、实际生效修订、target_id、output_slot_id、连接及场景身份。发生替换时结果包含 replaces_output_id。调用方用 resource_get 取得资源回执，按 URI 使用 resources/read 或受控下载读取 StageApplyResult，再通过 stage_output_get 查询该输出的固定摘要、状态序列及 ready、painted 状态。结果结构见[输出契约](../../contracts/schemas/stage-output.schema.json)。

## 输出生命周期

preview_id 的 expires_at 只限制首次受理应用的时间。已受理操作的恢复按原计划、当前目标及步骤事实继续。应用为候选分配稳定 output_id，后续读取通过该身份定位布局修订、目标和就绪状态。预检到期不会撤销已应用输出。

output_slot_id 由 profile_id、project_id、target_id 与场景原生身份确定，connection_generation 不参与槽位身份。同一项目在不同实际目标或不同场景的输出可以并存，应用 B 保留 A。在同一实际目标及场景应用新修订只替换该项目原槽位。另一项目经显式授权接管时，旧项目槽位退出占用，新项目槽位成为该目标场景的唯一 owner。

| 生命周期 | 布局与资源含义 |
| --- | --- |
| preparing | 候选尚未成为活动 owner，applied_revision 为 null，可加载至 ready |
| active | 占用活动槽位，实际生效修订为整数且 ready 为 true |
| retained | 已被替换且不占活动槽位，仍被计划外引用，保留原修订、来源设置、组件数据、媒体及只读 URL，ready 为 true |
| releasing | 沿所属原操作清理该输出获授权的对象，清理完成前保留必要访问及恢复资源 |
| released | 该输出清理完成，令牌与订阅已撤销，不返回 output_url |
| failed | 原应用或释放未完成，具体效果及继续恢复阶段由原 OperationDetail.recovery 表达 |

painted 为 true 必须同时 ready 为 true。active 与 retained 的 applied_revision 均为整数。retained 摘要提供 retained_reference_count 和 details_resource_id，通过详情资源指向的分页入口读取增长的引用集合。引用计数、资源持有及生命周期在同一状态提交中更新，并推进 state_sequence。

替换顺序为新候选 ready、OBS 变更与 verify、原子切换活动槽位、再释放已退出旧输出。切换前失败按原应用操作补偿，旧 owner、URL 和资源保持可用，失败候选不取代旧 owner。切换后旧输出清理失败保留已确认的新 owner，沿原应用操作的 recovery 继续旧输出清理；旧输出在清理完成前继续可访问。不得为重试清理而重复执行已确认的 OBS 应用。

旧来源存在计划外共享引用时保留其完整来源设置与依赖资源，旧输出转入 retained。每次引用变化及回收前重新枚举真实场景或组引用，不能仅凭缓存计数删除。引用归零后原子转入 releasing，并以稳定的回收操作及幂等记录安排清理。重新核对时新增引用则回到 retained，保留全部资源。不通过新应用挤占预算或删除 retained 资源。

## 显式释放与恢复

stage_output_release 携带 data_generation、output_id、expected_state_sequence 和 idempotency_key，返回 OperationReceipt。受理时校验当前 profile 的输出权限及状态序列，在同一事务登记原释放操作并推进 releasing。相同代际与幂等键返回原回执，不能重复清理。对已 released 输出使用新幂等键且当前状态序列匹配时，返回无新增外部效果的完成回执，状态序列保持原值；过时序列仍按冲突处理。

释放与应用、替换及恢复对同一输出串行。preparing、已有未结束应用或释放、以及尚未完成原恢复的输出不能受理另一释放执行，返回 OUTPUT_CONFLICT 并携带原 operation_id。调用方先查询原操作，需要停止候选时调用 operation_cancel，再沿 stage_restore 处理原操作。进入稳定可释放状态后重新读取 state_sequence。序列或归属已变化同样返回 OUTPUT_CONFLICT，避免旧读取撤销新状态。

释放在目标场景排他租约内核对原输出记录，只撤销该输出权限范围内的受管场景项及对象。外部引用的输入不删除，也不修改其设置。显式释放清理完成后提交 released 并撤销该输出令牌、订阅及不再需要的资源引用。释放活动输出时，原槽位和目标场景归属保留至清理完成；从 retained 发起释放不重新占用活动槽位。

部分释放失败将输出记为 failed，返回 RECOVERY_CONFLICT 并提供原 operation_id，保留继续恢复所需的设置、数据、媒体、凭据和引用。释放活动输出失败时原槽位继续被占用，恢复完成前其他项目不能接管。失败候选不占用旧输出槽位。stage_restore 对原 stage 应用或释放操作继续核对、清理或补偿，仅推进 OperationDetail.recovery，不把原 failed 执行状态改回 running，也不重新受理已完成阶段。

## 身份、令牌与并发

场景、来源和场景项分别记录身份；可用 UUID 优先，无 UUID 时保存名称、所属容器和场景项定位并回读验证。受管记录关联运行配置、项目、输出及创建操作。名称相同不直接触发覆盖。创建遇到“已存在”时回读类型、绑定与归属，只有同一操作或已授权受管对象才复用；其他冲突按计划使用新的受管名称或返回具体冲突。

输出 URL 使用只读凭据，绑定 data_generation、候选和资源范围。候选及输出身份在应用和恢复中稳定，输出凭据由输出状态管理。

OBS 套接字请求及资源锁由 broadcast 统一管理，直接 OBS 工具也使用该入口。apply 阶段按规范化实际 OBS 目标与场景原生身份取得跨进程排他租约，连接别名和同机不同 profile 共用协调键。target_id 需解析到同一实际目标，不能以 connection_id 或 profile_id 分割此租约。无法可靠确认原生场景身份或排他协调时返回 OUTPUT_CONFLICT，保持现有 owner。

全局来源设置按实际 target_id 与来源身份协调，场景项属性按其容器和项身份协调，层序变更取得场景或组的排序租约。跨场景共享来源将相关引用纳入读取和回读范围，多资源租约按固定顺序取得。OBS 变更事件使受影响的预检失效；执行前重新读取实际前置条件，目标场景租约覆盖应用、结果核对、槽位切换及补偿。释放和恢复重新取得相同协调键并核对 owner，不因进程退出或连接重连推定自己仍持有租约。

## 失败补偿

每步记录前值、计划写入、已确认后值及本次新建对象。超时先按原操作身份读取目标状态，再继续或补偿。

补偿前核对当前值仍对应本次已确认写入。若用户或其他控制器已修改该属性，保留其当前值并返回 RECOVERY_CONFLICT。既有浏览器来源恢复完整设置和变换；本次创建的对象只有仍归本次操作且未增加外部引用时才清理。

恢复完成以回读为准。部分恢复记录剩余对象和原因，提供原操作的继续恢复入口；新一次应用不会复用未核对的旧恢复状态。
