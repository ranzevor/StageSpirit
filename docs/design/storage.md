# 数据、配置与恢复

本文面向存储与配置实现，说明持久状态的归属、配置事务、激活、导入迁移及恢复方式。

持久配置记录期望值，活动快照记录已应用值，连接观察记录外部当前状态，操作账记录一次执行。配置恢复与动作恢复采用各自流程。

## 当前维护状态

D1 首批在 `<应用数据根目录>/profiles/<profile_id>/control.json` 保存 `format_version`、`profile_id` 和 `data_generation`。首次启动在取得实例锁后原子创建，后续启动读取同一代际。格式不支持、内容损坏或配置身份不符时返回启动错误。`instance.lock` 由系统文件锁控制，同一配置只允许一个活动实例，进程退出后释放。

应用数据根目录由 `--data-dir` 指定，省略时使用系统用户数据目录。profile ID 使用 1 至 64 个小写字母、数字、连字符或下划线，以字母或数字开头，并排除系统保留名称。后续数据库及恢复流程沿用这个独立维护状态。

## 数据布局

应用数据位于独立用户目录，按 profile 隔离。数据库、媒体、缓存和日志分目录，显式创建的备份保存到所选备份位置，启动不依赖源码工作目录。profile 的维护控制状态保存活动数据库位置、data_generation 和未完成切换阶段，独立于将被替换的数据库。

| 数据 | 存储与写入者 |
| --- | --- |
| 各模块配置、规则和语义映射 | SQLite；业务模块负责语义，settings 协调修订事务 |
| 事件、水位、分发和动作决定 | SQLite；live_events |
| 操作、幂等身份和恢复状态 | SQLite；runtime 保存通用状态，业务模块保存效果 |
| 展台项目、修订、计划和补偿 | SQLite；stage |
| 资源写入租约 | 对应控制模块；持久操作身份与内存连接代际关联 |
| 音频和图像 | 文件资源；数据库保存身份、摘要和引用 |
| 密钥及令牌 | 系统凭据库；配置只保存引用 |
| PCM 包络 | 有界内存通道 |
| 可变集合的版本投影与快照租约 | SQLite；所属模块提交投影，通用存储管理读取版本及到期回收 |
| 数据代际与数据库切换状态 | 独立维护控制状态；runtime 协调数据恢复 |

写入使用短事务和受管理队列。SQLite WAL 的读写与备份按目标文件系统验证；网络调用和音频播放不持有数据库写事务。媒体校验后才提交可用资源记录，中断临时文件可按资源状态回收。

## 配置保存与激活

请求携带目标分区、期望修订和明确的变更语义。模块先校验、准备新快照，settings 再事务写入配置与激活记录。提交后由模块应用，结果使用[配置回执](../../contracts/schemas/configuration-receipt.schema.json)表达。

saved_revision 表示持久值，active_revision 表示活动值。纯内存配置切换完成后两者相等；网络重配置失败保留已保存修订及具体错误。重试只再次应用指定修订，避免把旧连接回调记为新配置生效。

配置范围由 section 与可选 scope_id 共同确定。条件写入先校验 data_generation，再在同一数据代际内比较修订。连接以 connection_id 为范围，模型表情、嘴型和语义以内部 model_id 为范围，该身份绑定 VTS connection_id 与 provider_model_id，展台以 project_id 为范围。settings_get 返回该范围的标量设置、修订和集合入口，规则、映射、媒体等集合使用所属模块的分页接口读取。

active_revision 表示当前进程已经完成激活的修订。重启加载期间先保持未激活状态，再由参与者确认。激活结果同时核对当前保存修订与激活代际；较早修订的回调只补充原操作结果。settings_save 及领域配置保存提交后触发激活，settings_apply 用于再次应用当前保存修订；申请应用更早修订返回 REVISION_CONFLICT。未加载模型的配置保存结构校验结果及未激活原因，目标模型加载后继续应用同一已保存修订。

凭据变更先保存暂存引用身份，再写系统凭据库，配置事务提交后才能发布新引用。提交失败清理本次暂存引用。旧凭据的清理同时检查保存配置、活动快照和未完成操作的引用，待新的活动配置完成替换后再释放。进程中断后按引用关系恢复尚未完成的暂存处理。

语义切换的在播处理见[形象与表演](avatar-performance.md)。重启恢复未完成的配置激活记录，保持原配置和新配置的实际状态可查询。

## 固定快照与版本回收

不可变事件以 data_generation、sequence 排序键和固定上界读取。操作状态、连接、规则、媒体等可变列表保存版本投影，每次变更在所属模块事务中写入带有效版本区间的列表摘要，删除保留版本墓碑。首个请求固定集合读取版本，续页按同一版本的成员、摘要和排序生成，后续修改与删除不改变该快照。

游标指向有期限的快照租约，绑定运行配置、数据代际、集合、筛选和排序。页大小受接口上限控制，查询按索引与 keyset 继续；详情查询读取当前对象，并返回当前修订。列表中的旧摘要不覆盖详情返回的新状态。

快照有效期从首个请求计算，续页不延长。租约数量和版本保留预算按运行配置限制，超限在建立快照前返回 RESOURCE_LIMIT。租约过期返回 CURSOR_EXPIRED；版本回收只清理已经没有有效读取租约、操作或业务引用的历史投影。事件清理也保护有效快照覆盖的记录。实现使用短事务，跨页不保持数据库读事务。

## 导入、迁移与保留

导出包含格式版本、来源 data_generation、运行配置修订，以及按 section、scope_id 唯一标识的分区数组。每个分区包含保存修订、值及凭据引用。导入目标由当前运行实例确定，来源 profile_id 作为导出信息保留。源分区修订用于核对导入内容，目标分区按自己的修订递增。导入前重新校验目标作用域与凭据绑定。

settings_import 的 preview 阶段验证完整内容并固定资源摘要、目标 data_generation、运行配置修订、strategy 和显式删除范围。commit 使用同一 preview_id 和 expected_revision 事务提交。merge 更新包内给出的分区与字段，缺省字段保留；replace 用包内完整集合替换目标配置，预览列明将删除的分区。delete_sections 在 merge 中表达明确删除，同一范围同时出现在导入集合和删除集合时拒绝。值为 null 按分区字段类型处理。导入提交后，各分区分别按配置激活流程生效。

数据库迁移使用递增版本和独占维护窗口。可事务完成的迁移失败后回滚并保留原有数据。涉及文件格式切换或降级的迁移先检查已选择的恢复资源，再进入维护阶段；不兼容版本保持原数据并返回 MIGRATION_REQUIRED。

已接收业务事件默认持久保存；自动删除由显式保留策略触发。同一数据代际内，记录被清理的序列区间及最早可读序列。只有本次排他续读范围与已清理历史区间相交时才返回 HISTORY_GAP；after_sequence 等于最早可读序列减一时可从该事件正常续读。恢复查询保留实际缺失区间。有效订阅水位、未完成恢复快照和被引用媒体受引用检查保护。磁盘容量不足返回实际持久化错误，不报告未提交数据已保存。

settings_backup 或明确启用的备份策略才创建备份。备份固定数据库快照，并保护复制期间被引用媒体，完成后提供包含媒体实体及清单的资源。settings_restore 先预览版本、目标和差异，再在维护窗口内提交恢复；失败保留恢复前的有效数据。恢复时先校验新数据库和媒体，将当前恢复操作、恢复所需的原操作去重身份及效果核对记录带入新库，在维护控制状态中准备新 data_generation，再切换活动数据库并发布新代际。重启先核对活动数据库、数据库内的代际与切换阶段，选择已完成的切换结果后开放业务入口。恢复失败回到原库时不发布尚未生效的候选代际。

事件 sequence、配置和项目修订保留各自数值，读取上下文使用新 data_generation；它们不能与恢复前的同值混用。恢复前的游标、预检、编辑会话和输出授权失效，旧水位及变更请求返回 DATA_GENERATION_CHANGED 和当前代际。恢复前的外部目标与活动输出重新核对，数据恢复完成与重新应用 OBS 布局分别记录。已接受原操作的重复请求保留原受理代际，只返回原结果或进入原操作核对，不能新增外部效果。连接及模型代际随恢复更新，当前恢复操作继续可查询。备份、导出和恢复各有独立操作身份。凭据跨设备恢复按系统凭据库能力重新绑定。配置读取及日志不输出明文密钥。取舍见 [ADR 002](../adr/ADR-002-local-state.md)。
