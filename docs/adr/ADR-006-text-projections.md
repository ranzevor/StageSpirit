# ADR-006 合成正文与字幕投影

本文是面向语音、字幕和语义实现的设计记录，说明同一播报正文按不同用途生成文本视图的选择。

## 背景

发声标签用于控制语音提供方，观众字幕需要展示播报正文，关键词动作需要排除标签对匹配的影响。各用途还需要关联到同一次播放和正文修订。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 在 TTS 输入端统一删除标签 | 文本处理集中，标签对应的发声控制随之丢失 |
| 全部消费者直接使用合成正文 | 保留原输入，字幕会展示表演标签并影响分句 |
| 按合成、字幕和匹配分别投影 | 各用途保持明确语义，需要统一身份与投影规则 |

## 设计选择

speech 保留用于发声的 ASCII 方括号内容，stage 从播放正文生成独立字幕，删除全部 ASCII 方括号块及其中内容。performance 使用排除发声标签的匹配正文。

普通 TTS 请求只包含语音设置。三个文本视图使用同一播放身份和正文修订关联，合成正文作为播放事实保留。字幕通过组件 state_sequence 排序，初始 hidden 可以没有播放身份，播放后的清理继续校验当前播放身份。

## 理由与代价

分别投影使语音控制、观众展示和关键词匹配各自保留必要内容。投影需要处理嵌套、多行、未闭合尾部及纯标签发声，字幕在清理后进行分句。正文对齐保存合成正文码点区间与音频区间的关联，独立记录 alignment_source。实际播放时钟与正文对齐来源分开，PCM 播放且缺少正文时间戳时仍使用 text_estimate 对齐，原生生命周期消费者沿用播放器起钟信息。

## 重新选择条件

提供方增加结构化发声控制时，可评估该提供方的输入适配。合成正文、字幕和匹配视图继续按各自用途维护，并保持播放身份和正文修订关联。

## 关联需求与验收

发声正文保持、字幕过滤、纯标签隐藏、原播放事件及分句行为按对应场景验证。
