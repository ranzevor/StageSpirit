# ADR-004 工具注册与渐进发现

本文是面向 MCP 接入实现与技术评审的设计记录，说明工具来源、能力发现及集合查询的组织方式。

## 背景

提供方和业务工具数量会增长，工具说明、参数 Schema 和路由需要保持一致。调用方还需要在尚未建立连接时发现可配置渠道，并在网络短暂断线后继续处理原操作。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 全量常驻工具与完整列表响应 | 入口集中，目录与单次结果随数据量增长 |
| 随连接状态动态增删工具 | 目录反映当前连接，网络变化会触发频繁目录变化 |
| 按启用能力组发现并分页查询 | 保留启动入口，按业务需要读取目录与结果 |

## 设计选择

单一类型化注册来源生成工具 Schema、路由和参数资料。工具按已启用能力组提供，core 保留启动和配置所需工具。提供方发现可在建立连接前使用，短暂断线保留已启用工具。

大型集合默认游标分页，详情按身份读取，媒体和完整导出使用资源引用。空列表所需的目录状态与来源保留在集合元数据中。不可变事件按同数据代际的稳定序列续读，可变集合使用版本化摘要快照。快照到期后按对应查询类型重新建立上下文。事件保留必要业务字段和完整正文。

变更请求携带 data_generation，配置保存后触发激活，settings_apply 再次应用当前保存修订。传输取消与持久操作取消分别处理；stage_apply 的完成结果资源提供 output_id，语义运行摘要通过 semantic_status_get 查询。

## 理由与代价

分组控制目录规模，分页控制单次载荷，统一注册减少接口漂移。客户端需要维护目录修订和同筛选游标，只支持全量目录的上游需要本地快照缓存。

## 重新选择条件

所选 MCP 协议或消费客户端的目录发现能力发生变化时，更新发现机制与互通矩阵。接口变更按兼容版本管理，启动配置和业务字段语义继续保留。

## 关联需求与验收

真实客户端、能力组变化、目录分页及业务分页分别验证。
