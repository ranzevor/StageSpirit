# ADR-001 模块化运行架构

本文是面向架构实现与技术评审的设计记录，说明本地运行结构、状态所有权和模块协作方式的选择。

## 背景

StageSpirit 同时管理音频播放、平台事件、模型控制和 OBS 长连接。各领域的状态、完成判据和失败恢复不同，本地安装还需要统一装配与关闭。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 单一集中管理器 | 装配直接，业务状态与恢复职责集中耦合 |
| 模块化单体 | 复用进程与连接，按业务状态保持公开边界 |
| 多服务部署 | 便于单独隔离，增加部署与跨进程协调 |

## 设计选择

采用单进程模块化单体，接入层、应用服务、领域端口和适配器各有职责。runtime 管理生命周期和操作账，业务模块拥有自己的完成判据与状态。

参数控制统一由 avatar 写入，OBS 控制统一由 broadcast 写入。settings 通过参与者接口协调持久配置与激活。跨模块通过公开端口交换数据与命令。

## 理由与代价

本地安装和长连接可在同一进程内复用，按业务状态划分边界缩小维护范围。该选择需要稳定端口和受管理后台任务，进程故障仍影响同一实例。

## 重新选择条件

出现实际进程隔离或吞吐需求时，评估相应模块的独立进程，同时保持其公开契约和状态所有权。
