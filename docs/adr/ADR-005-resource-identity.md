# ADR-005 应用与外部资源身份

本文是面向安装、配置与 OBS 集成实现的设计记录，说明应用隔离、显式绑定和受管资源归属。

## 背景

同名场景或来源可能属于不同对象。混用配置目录、令牌和插件身份会使独立应用访问其他资源，恢复操作也需要区分本次写入与用户后续修改。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 按名称创建或覆盖 | 定位简单，名称无法单独确定对象及归属 |
| 依赖缓存中的对象列表 | 减少读取，外部修改或删除会使缓存失效 |
| 独立身份、显式绑定与执行前回读 | 增加状态读取，能够核对目标及可恢复范围 |

## 设计选择

应用、运行配置、数据代际、连接和受管对象分别维护身份。model_id 是绑定 VTS 连接与原生模型的内部身份；target_id 表达外部服务的写入协调域，连接别名访问相同目标时共用协调器。

OBS 名称用于展示或解析，实际复用前回读类型、绑定与归属。同名、相同 URL 和名称前缀不自动产生资源归属。只读来源绑定创建受管场景项，复用既有场景项按明确属性授权，纳入受管排序需要排序权限。受管场景项在目标底部按布局层序排列，其他场景项的相对顺序保持原值。

全局来源、场景项和排序容器分别确定可写范围与租约，共享来源核对全部引用。预检身份用于首次受理应用，输出身份用于持续访问和恢复，各自按所属生命周期及 data_generation 管理。

## 理由与代价

身份核对能区分可复用对象与冲突，并保护既有资源。实现需要保存所有权记录、来源映射和恢复快照。已经删除或被外部修改的资源需要重新核对。

## 重新选择条件

目标服务提供更稳定的原生身份或所有权接口时，评估对应绑定方式，并保持既有对象保护和恢复冲突判据。

## 关联需求与验收

隔离安装、同名冲突、失败补偿和用户后续修改按对应需求与场景验证。
