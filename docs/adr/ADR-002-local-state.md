# ADR-002 本地状态存储

本文是面向存储实现与技术评审的设计记录，说明结构化状态、媒体和凭据的存放方式。

## 背景

配置、历史、任务与展台修订需要持久化和事务。音频与图片需要文件资源访问，密钥需要与普通配置分离。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 多份 JSON 文件 | 简单配置直观，跨对象事务与历史查询需要额外协调 |
| SQLite 与文件资源 | 提供单机事务和查询，媒体保持独立资源 |
| 远程数据库 | 支持跨主机访问，增加连接、部署与运行依赖 |

## 设计选择

结构化状态使用 SQLite，媒体使用文件资源，密钥使用系统凭据库。配置修订、运行观察和一次性操作分别保存。配置通过版本化 JSON 导入导出，保留运行配置修订及模型、连接等分区范围。备份由明确操作或已启用策略触发。

可变列表保存版本投影，以有期限的读取版本固定分页成员、摘要与排序，跨页释放数据库事务。不可变事件使用序列上界，保留清理记录实际历史缺口。

数据恢复生成新的 data_generation，游标、水位、条件写入和输出授权绑定该代际。数据库位置、活动代际和切换阶段由独立维护控制状态协调，原恢复操作及必要去重身份随切换保留。

## 理由与代价

SQLite 适合本地安装并提供事务和查询。版本投影增加写入与历史回收成本，快照租约约束其保留范围；数据代际使恢复后的同值修订和水位能够区分。单机数据库存在写入和磁盘边界，备份需要关联媒体清单，系统凭据的搬迁能力随操作系统而异。

## 重新选择条件

明确需要多主机共享写入时重新评估数据库方案，并保留配置版本、事务及资源引用的契约。

## 关联需求与验收

重启、并发保存、导入迁移及事件恢复按对应需求和场景验证。
