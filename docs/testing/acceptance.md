# 验收场景

本文是面向测试实现和验收的场景规格，每项保留稳定 ACC 标识，并给出关联需求、输入、步骤及预期观察。测试方法见[测试设计](README.md)。

## 运行、配置与安装

<a id="acc-ind-001"></a>

### ACC-IND-001 独立安装与外部资源隔离

关联需求为 [REQ-IND-001](../requirements/README.md#req-ind-001)。

测试类别为 `installed-package`。

**输入**

- 干净应用数据目录
- 安装后的制品
- 独立OBS/VTS测试身份

**步骤**

1. 从源码目录之外启动
2. 检查导入位置、数据路径和外部资源归属
3. 移除其他项目目录访问后执行代表性工具

**预期**

- 启动和功能不依赖其他项目
- 旧配置未被隐式读取
- 受管资源可按本项目身份识别

### ACC-RUN-003 幂等、取消与默认目标解析

关联需求为 [REQ-RUN-002](../requirements/README.md#req-run-002)。

测试类别为 `contract`。

**输入**

- 可控慢适配器

**步骤**

1. 并发提交相同键和相同请求
2. 再提交相同键不同请求

<a id="acc-run-004"></a>

### ACC-RUN-004 回执丢失与迟到响应

关联需求为 [REQ-RUN-002](../requirements/README.md#req-run-002)。

测试类别为 `integration`。

**输入**

- 外部执行后回执丢失
- 进程重启
- 迟到完成响应
- 数据库恢复前已受理且外部效果尚未核定的操作

**步骤**

1. 用原幂等键查询操作
2. 按目标能力核对结果
3. 在新代际建立后交付旧响应
4. 恢复数据库后按原操作身份查询或执行其允许的恢复，再尝试把旧请求作为新动作提交

**预期**

- 同一逻辑操作不重复创建
- 语音不因重启自动从头播放
- 无法确认的效果保留unknown
- 旧响应只能补充旧事实，不能复活新任务
- 原操作仅按已有身份核对或恢复，旧代际请求返回 DATA_GENERATION_CHANGED 及当前代际，外部动作不因数据恢复重新执行

### ACC-CFG-003 导入、迁移与显式备份恢复

关联需求为 [REQ-CFG-002](../requirements/README.md#req-cfg-002)。

测试类别为 `integration`。

**输入**

- 版本化配置包
- 数据库和引用媒体
- 受控迁移故障
- 备份后新增的事件、修订、旧游标及续读水位
- 数据库切换前后的 data_generation 与持久切换状态

**步骤**

1. 预览后事务导入
2. 显式创建一致备份并取得资源
3. 注入事务迁移中断，检查原数据
4. 预览所选备份并提交维护恢复，在数据库切换前后分别注入中断再重启
5. 在未启用备份策略的配置中执行普通启动
6. 分别在数据库切换前后注入中断，重启后读取数据库、数据代际与切换状态

**预期**

- 配置导入没有部分提交
- 凭据缺项被明确保留为待绑定项
- 事务迁移故障保留原数据
- 恢复后的数据库与媒体引用一致
- 恢复操作身份与幂等记录跨重启保持，历史未完成外部操作进入核对
- 备份仅由明确操作或已启用策略产生
- 每次恢复生成新 data_generation，并与数据库切换状态一并持久化，中断恢复后数据库和代际对应一致
- 恢复前后的事件序列与修订分别属于各自数据代际

### ACC-EVT-005 匿名事件与稳定水位续读

关联需求为 [REQ-EVT-001](../requirements/README.md#req-evt-001)、[REQ-EVT-002](../requirements/README.md#req-evt-002)。

测试类别为 `integration`。

**输入**

- 匿名会员事件及缺少上游发生时间的事件
- 相同 received_at 的多条不同事件
- 消费中断期间新增的事件
- 恢复前的 data_generation、游标和 after_sequence，以及恢复后的数据代际
- 显式保留策略删除部分历史后，续读区间实际包含已删除事件的消费水位

**步骤**

1. 保存事件并按 sequence 分页
2. 记录已处理水位后中断消费
3. 使游标过期，以 after_sequence 建立新查询
4. 在同一代际内删除已允许清理的历史，再以旧消费水位续读，并以最早可读序列减一查询保留边界
5. 恢复数据库后，分别提交恢复前的游标与 data_generation、after_sequence 组合

**预期**

- 上游未提供的 UID、发生时间保持省略，匿名属性与会员数量保留
- 同一 data_generation 内的本地 sequence 严格递增，相同时间的不同事件分别返回
- 新查询覆盖水位之后的已保存事件，event_id 用于重复通知去重
- 续读区间包含已删除事件时返回 HISTORY_GAP 和最早可读序列，调用方可据此明确选择新的读取起点
- 同代际 after_sequence 等于最早可读序列减一时，从最早可读事件正常续读
- 旧代际游标和水位返回 DATA_GENERATION_CHANGED 及当前代际，序列仅在同一代际内比较

<a id="acc-tts-004"></a>

### ACC-TTS-004 合成资源、队列顺序与实际播放

关联需求为 [REQ-TTS-004](../requirements/README.md#req-tts-004)。

测试类别为 audio-integration。

**输入**

- 可解码 PCM 与只支持原生播放的提供方
- 在播 A，按顺序受理的待播 B（priority 5）、C（priority 9）、E（priority 9）
- priority 0 且 interrupt_current 为 true 的替代任务 D
- priority 5 的慢合成队首与后到 priority 9 请求、已进入 starting 的任务、受控停止确认及停止结果未知
- 64 个待播项、并发合成计数、重复幂等请求、不支持停止的旧播放适配器及使用另一连接的替代任务

**步骤**

1. 仅合成并读取文件资源，再播放并比较采样位置与进度事件。
2. 在 A 播放时受理 B、C、E，改变其合成完成顺序，比较下一播放者及同级顺序。
3. 保持最高优先队首未就绪，观察后续已就绪任务；再受理更高优先任务，并在另一任务已取得播放权进入 starting 后提交高优先请求。
4. 单独受理打断任务 D，延迟停止确认及 D 的合成完成，观察真实启动时刻；切换中提交另一个新打断及 D 的相同幂等请求。
5. 分别注入 D 合成失败、D 取消、A 自然结束与停止竞争、停止结果未知，读取原操作及队列。
6. 分别停止指定在播操作与待播操作，观察其他待播项。
7. 填满待播容量后提交普通及打断请求，降低容量和合成并发，再使用不支持停止的适配器发起打断。

**预期**

- 仅合成返回文件资源且不占播放时间轴，原生播放适配器对文件合成返回 UNSUPPORTED_CAPABILITY。
- 播放事件对应真实设备生命周期与采样进度，prepared 或请求受理不会提前产生 started。
- priority 数值大者优先，普通顺序为 C、E、B；相同幂等请求保留原操作与 enqueue_sequence。
- 队首未就绪时后续低优先或同级任务等待，新到更高优先任务可成为队首；starting 后本次选择固定，A 的在播声音不被普通优先级请求打断。
- 受理 D 后请求停止当前播放，D 取得一次下一播放权，其 priority 0 不使其落后普通待播项；旧播放终止、设备及控制释放、D 音频就绪后才启动 D。
- 同槽位第二个新打断受理前返回 PLAYBACK_SWITCH_BUSY，D 的重复请求仍返回原操作；D 取得播放权进入 starting 时消费保留权，之后新的显式打断可针对 D 受理。
- D 失败或取消释放保留权，其他待播项继续按优先级及 FIFO 执行；旧声音保留实际播放位置，已停止部分不会自动重播。
- 自然结束与停止竞争保留真实终态；停止未知时沿原操作核对，替代声音继续等待。
- 停止准确作用于指定操作，结束与中断对同一授予只释放一次。
- 默认待播容量为 64，当前播放所有者不计入，D 等待时计入；合成并发不超过配置值与适配器上限的较低者。
- 满额返回 QUEUE_FULL，有旧播放且其适配器不支持停止时返回 UNSUPPORTED_CAPABILITY，空闲槽位无需旧播放停止能力；跨连接切换核对旧任务适配器，受理失败不停止当前声音。降低预算不丢弃已有任务，降低并发等待现有合成退出。
- 合成已进入 running 后等待播放保持该通用操作状态，内部队列阶段单独查询。

- StageApplyResult 包含输出身份、实际生效修订、profile_id、target_id、output_slot_id 及替换时的 replaces_output_id，stage_output_get 返回固定摘要。
- 不同场景或目标的输出并存，同槽位新输出替换旧输出，连接重建不改变槽位。
- 同一实际目标场景只保留一个项目 owner；跨项目接管必须在 prepare 固定 replace_output_id，省略授权、owner 漂移及跨 profile 自动接管返回 OUTPUT_CONFLICT。
- 同目标连接别名和同机不同 profile 的应用共享场景排他协调键。
- 不透明背景只在最低层绘制一次，上层浏览器平面保持透明，原生捕获按布局层序可见
- 捕获框饰出现在其显式指定的捕获上方或后续层，透明皮肤和空布局的画面符合各自布局定义

### ACC-STG-005 恢复冲突与外部引用

关联需求为 [REQ-STG-003](../requirements/README.md#req-stg-003)。

测试类别为 `obs-stage-integration`。

**输入**

- 本次写入后用户又修改的来源
- 新增外部引用的本次创建对象
- 被替换且仍有外部引用的旧输出、引用归零后又出现新引用的回收竞争
- 活动及 retained 输出的显式释放、过时 state_sequence、释放部分失败及重复幂等请求

**步骤**

1. 启动原操作恢复
2. 比较当前属性与本次最后确认值。
3. 替换已有外部引用的输出，读取 retained 摘要、URL、组件数据及引用分页；减少引用到零并在回收前新增引用。
4. 对 active 与 retained 输出显式释放，注入过时序列、未完成应用及部分清理失败，再沿原操作恢复并重复幂等请求。

**预期**

- 保持用户新修改并返回RECOVERY_CONFLICT
- 有新增外部引用的对象不被删除
- 未冲突的本次变更按记录恢复
- 部分恢复准确列出剩余对象。
- 旧输出有外部引用时为 retained，ready 为 true，保留完整来源设置、原布局、媒体、组件数据及只读 URL；引用数量有界返回，明细分页。
- 引用归零后重新核对并进入 releasing，新增引用时回到 retained，资源预算不足保持已有输出。
- 显式释放核对当前状态序列与归属，只清理授权对象，外部引用输入保留设置；完成后 released 且撤销令牌、订阅和 URL。
- 未完成应用、释放或恢复不能由新释放绕过，返回 OUTPUT_CONFLICT 及原操作；旧序列不能撤销新输出。
- 活动输出释放失败继续保留原槽位占用，RECOVERY_CONFLICT 指向原恢复，完成前其他项目不能接管；retained 释放不重新占用活动槽位。
- 同一幂等释放复用原操作，对已 released 输出以新键和当前序列调用取得无新增外部效果的完成回执；恢复只推进原 recovery，已确认的应用或清理步骤不重复执行。
