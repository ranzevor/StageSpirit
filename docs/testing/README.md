# 测试设计

本文面向测试编写和验收执行，说明测试层次、输入来源及观察方式。具体场景在验收设计维护，需求规格定义对应义务。

[需求规格](../requirements/README.md) · [验收场景](acceptance.md) · [性能验收](performance.md)

场景按运行配置、事件、语音、形象、展台及接口安全分组。稳定 ACC 标识关联需求，标题说明具体观察对象。

## 验证层次

| 层次 | 观察对象 |
| --- | --- |
| 单元 | 文本投影、关键词匹配、参数选择等确定性规则 |
| 契约 | 请求响应结构、字段、错误及跨模块保证 |
| 集成 | 实际存储、配置事务、模块协作、并发及恢复 |
| 安装制品 | 独立环境中的包、命令、静态资源与可选依赖 |
| 真实目标 | MCP 客户端与语音、VTS、OBS 及直播平台的实际交互效果 |
| 性能 | 参考负载下的分段时延、吞吐、进程资源、页面帧耗时和恢复 |

测试按当前改动选择相关正常、边界、错误与恢复分支。已有通过结果在被证明对象及相关条件保持一致时复用。

## 执行与判断

先按场景建立初态与独立预期，再运行对应入口并观察实际结果。真实服务联调使用 MCP 客户端、HTTP/WebSocket 和目标服务 API，外部写入使用相应授权及隔离对象。展台视觉验收使用 OBS 截图 API 取得合成测试场景画面，比较不透明与透明皮肤、原生捕获前后层、框饰及空布局。

配置验收分别观察持久修订和活动修订，长操作验收分别观察完成状态与已发生效果。恢复验收同时比较 data_generation、数据库切换状态及原操作身份，事件序列、修订和组件状态仅在所属代际内比较。可变集合同时检查固定列表投影和当前详情，订阅在快照水位前后注入并发更新、重复与迟到消息。

播放验收分别核对 playback_clock 与 alignment_source，使用原始开始时刻和时钟域比较延迟消费者。并发验证使用受控屏障与故障注入，检查冷却决定、编辑批次、表情切换和资源锁的实际结果。本地 Web 通过请求与 DOM 观察检查 Host、Origin、CSRF、会话、令牌撤销和外部文本处理。出现失败时定位受影响机制，修复后执行对应场景及其实际消费者。

性能执行按[性能验收](performance.md)固定的参考环境、负载、统计窗口和数值目标组织。D1 至 D6 分别运行所属链路，D6 汇合完整参考负载；外部适配器同时记录完整端到端与控制器分段时延。功能场景的状态正确性与对应性能阈值分别判断。
